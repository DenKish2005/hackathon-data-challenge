# Инструкции для агента

Эти правила действуют для всего репозитория при каждой задаче, если пользователь явно не задал другой порядок.

## Обязательный цикл работы

1. В самом начале, до изменения файлов, проверить `git status --short --branch`. Сохранить все существующие изменения пользователя, не перезаписывать и не удалять их.
2. Работать в ветке `main`. Если активна другая ветка, безопасно переключиться на `main`, сохранив существующую работу. Затем обязательно выполнить `git pull --ff-only origin main` до выполнения задачи. Если синхронизация не удалась, сначала устранить причину; не продолжать работу на устаревшей версии молча.
3. Выполнить запрошенную пользователем задачу.
4. Запустить проверки, подходящие для сделанных изменений, и проверить итоговый diff.
5. Добавить в индекс только файлы и изменения текущей задачи и выполнить `git commit` с понятным описанием результата. Не включать посторонние изменения пользователя. Если задача не изменила файлы, пустой коммит не создавать.
6. После успешных проверок и коммита обязательно выполнить `git push origin main`. Если новых локальных коммитов нет и ветка синхронизирована, push не требуется. При отклонении push из-за новых удалённых коммитов подтянуть их с помощью `git pull --rebase origin main`, разрешить конфликты с сохранением чужой работы, повторить затронутые проверки и push. Не использовать force push.
7. В ответе кратко сообщить результат, проверки и статус отправки в GitHub. Если pull, commit или push не удалось завершить, явно сообщить об этом и причине.

Для задач агента этот цикл с прямой отправкой в `main` имеет приоритет над рекомендациями о рабочих ветках и Pull Request в других документах проекта. Выполнение pull, commit и push в рамках задачи уже запрошено пользователем; дополнительное подтверждение намерения не требуется. Обязательные разрешения среды выполнения по-прежнему соблюдаются.
