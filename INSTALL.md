# CQA User Audit — установка и запуск

## Что это

Повторно используемый Codex skill, который **исследует Freedom CQA глазами пользователя в реальном браузере**, фиксирует все важные действия/реакции, сохраняет P0/P1/P2 баги и генерирует отчёт для отдельного Codex-сеанса исправлений.

Skill **не содержит выполненный аудит**. Он предоставляет процедуру, матрицу и инструменты отчётности; фактические результаты появятся только после его запуска в окружении с вашим приложением.

## Установка для всей команды в репозиторий

1. Распакуйте ZIP **в корень** `hackathon-data-challenge` с сохранением структуры. В итоге должен существовать файл:

   `.agents/skills/cqa-user-audit/SKILL.md`

2. Запустите Codex из корня репозитория. Если навык не виден, перезапустите Codex и введите `/skills`.
3. Вызовите навык в Codex:

   `$cqa-user-audit Проведи полный независимый пользовательский аудит Freedom CQA на локальном приложении с синтетическими данными. Не исправляй код. Пройди все P0, затем P1/P2, записывай каждое действие, сохрани BUGS.json, ACTION_TRACE.jsonl, COVERAGE.csv, REPORT.md, FIX_PROMPT.md в .runtime/qa-audit/<run-id>. Если что-то не можешь выполнить — пометь BLOCKED/NOT_RUN, а не PASS.`

**Внимание:** проектный `AGENTS.md` содержит обязательные Git правила. Для аудита используйте отдельную локальную БД и сохраните отчёты в `.runtime/` (игнорируемая директория), а не в Git. Команда не должна очищать вашу настоящую БД.

## Второй запуск: исправление по отчёту

После аудита откройте **новый** сеанс Codex и передайте:

`Исправь подтверждённые дефекты на основании локального файла .runtime/qa-audit/<run-id>/FIX_PROMPT.md. Сначала прочитай BUGS.json/REPORT.md/trace, воспроизведи каждый дефект в браузере, затем внеси минимальные исправления с регрессионными тестами, проверь и создай FIX_VERIFICATION.md. Не делай вид, что гипотеза причины из отчёта доказана.`

Проверка структуры отчёта:

```bash
python .agents/skills/cqa-user-audit/scripts/validate_report.py .runtime/qa-audit/RUN_ID
```

Повторное создание handoff:

```bash
python .agents/skills/cqa-user-audit/scripts/make_fix_prompt.py .runtime/qa-audit/RUN_ID
```

## Режимы

- `UI_ONLY`: browser/UI с контролируемыми ответами, не измеряет качество модели.
- `INTEGRATION`: реальный локальный backend/SQLite, mock для проверки интеграции.
- `LIVE_LOCAL`: реальный локальный Ollama на **синтетических** данных; время и модель фиксируются.

Не включать приватные разговоры, подписанные URL, `.env`, cookies, персональные данные, bearer tokens и реальные аудиозаписи в отчёт или репозиторий. Без независимой ручной разметки нельзя говорить об измеренной точности LLM.
