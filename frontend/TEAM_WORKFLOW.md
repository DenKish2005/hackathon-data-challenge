# Как работать втроём без лишних конфликтов

Для автоматического агента приоритет имеют актуальные инструкции корневого `AGENTS.md`: pull → задача → проверки → commit → push в `main`. Рекомендации по отдельным веткам ниже относятся к участникам команды, если вы договорились о таком порядке.

У каждого — отдельный клон проекта, своя ветка и своя зона файлов. На сервере развёртывает один назначенный участник. Не переключайте ветки одновременно в одной общей папке.

| Участник     | Зона                                                        | Ветка               |
| ------------ | ----------------------------------------------------------- | ------------------- |
| 1 — фронтенд | `frontend/**`                                               | `feat/cqa-frontend` |
| 2 — сервер   | `backend/**`, инфраструктура по согласованию                | `feat/cqa-backend`  |
| 3 — ИИ       | `evaluation/**`, `agents/**`, промпты и проверочные примеры | `feat/cqa-ai`       |

Названия серверных и ИИ-папок согласуйте до начала работы. Текущий `src/tokenops_guard/` — существующая библиотека; фронтенд её не изменяет.

## Цикл задачи

1. Взять конкретную задачу и завести ветку от свежего `origin/main`.
2. Менять файлы своей зоны и запустить проверки.
3. Добавить в коммит конкретные файлы.
4. Сделать коммит и push своей ветки.
5. Открыть Pull Request в `main`, описать результат и проверки.
6. Получить проверку товарища и сливать по одному PR за раз.

```bash
git fetch origin
git switch -c feat/название-задачи origin/main
# Выполнить задачу и проверки.
git add frontend/нужные-файлы
git commit -m "Описание результата"
git push -u origin feat/название-задачи
```

Для фронтенда:

```bash
cd frontend
npm ci
npm run build
# При запущенном dev-сервере и доступном Chromium:
npm run test:smoke
```

Перед слиянием:

```bash
git fetch origin
git merge origin/main
# Разрешить конфликты в своих файлах, повторить затронутые проверки.
git push
```

Не делайте force push в чужую или общую ветку. Не включайте чужие незакоммиченные файлы в свой PR.

## Общие договорённости

- Формат API согласуют авторы клиента, сервера и ИИ: диалог, сообщение, критерий, оценка, апелляция.
- Изменения полей API сначала обсуждаются, затем обновляются на обеих сторонах.
- Общие файлы в корне, CI и Compose в каждый момент меняет один назначенный участник.
- Секреты и подписанные URL остаются на сервере.

Фронтенд использует синтетические данные. Контракт для независимой разработки сервера описан в `frontend/README.md`. Реальные оценки, версии правил и полную историю пересмотра сохраняет backend.
